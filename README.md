**MINIAWE** 是一个聚焦小程序开发的开源组织，围绕多端场景，沉淀可复用的组件、工具链与最佳实践，帮助开发者少走弯路、快速交付。

**主题：轻量 · 多端 · 可复用**

## 🎯 我们关注什么

- **多端一致性**：一套代码思路，覆盖微信、支付宝、抖音、H5 等多端场景。
- **轻量可复用**：组件与工具保持小而专注，按需引入，不绑架技术栈。
- **工程化最佳实践**：从脚手架、构建、调试到发布，补齐小程序开发链路的短板。
- **开发者体验**：清晰的文档、可运行的示例、可预期的行为。

## 📦 项目方向

| 方向 | 说明 |
| --- | --- |
| 🧩 组件库 | 高频业务组件与基础 UI 组件，多端适配、开箱即用 |
| 🛠️ 工具链 | 脚手架、构建插件、多端转换与调试工具 |
| 📚 最佳实践 | 目录规范、性能优化、状态管理与测试方案 |
| 🧪 示例模板 | 可直接运行的起步模板与场景化 Demo |

## 🚀 快速开始

```bash
# 克隆示例模板（以实际仓库名为准）
git clone https://github.com/MINIAWE/<repo-name>.git
cd <repo-name>
npm install
npm run dev
```

更多用法请查看各仓库的 README 与文档站点。

## 🤝 参与贡献

我们欢迎任何形式的贡献：提交 Issue、完善文档、修复 Bug、贡献组件或工具。

1. 阅读 [贡献指南](CONTRIBUTING.md) 与 [行为准则](CODE_OF_CONDUCT.md)
2. Fork 仓库并创建特性分支：`feat/your-feature`
3. 提交前确保通过 lint 与测试
4. 发起 Pull Request，描述动机与改动内容

> 第一次参与开源？从带有 `good first issue` 标签的任务开始是个不错的选择。
